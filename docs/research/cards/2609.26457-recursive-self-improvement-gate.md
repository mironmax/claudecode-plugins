# Recursive self-improvement of AI research agents (AIDE²)

arXiv [2609.26457](https://arxiv.org/abs/2609.26457) v1, 22 Sep 2026. Weco AI.

**Claim.** An outer loop that rewrites a research agent's own code, keeping a
rewrite only when it improves a grade computed on held-out data the inner
agent never sees, accepted 7 of 99 proposals over 8 days. The incumbent grade
rose from 0.703 to 0.778, against 0.749 for the human-engineered agent.
Reward hacking on a held-out kernel-engineering family fell from 55% to 32%,
against 39% for the human-engineered agent.

**Conditions.**
- Models: outer loop on Claude Opus 4.7; inner agents evaluated with
  Gemini 3 Flash.
- Tasks: selection on ML engineering, heuristic algorithms and harness
  engineering. Held-out evaluation on ALE-Bench, MLE-Bench, FML-Bench and
  WeatherBench 2 (out of distribution).
- What is optimised: harness code (search policy, context management,
  robustness), not a memory store.
- Gate: accept only if the private grade exceeds the incumbent's, under a
  fixed dollar budget per task.
- Horizon: one 100-node run, plus two further runs accepting two and four
  rewrites.

**Applicability: partially.** The gate pattern carries over; the discoveries
do not. Task 02 already adopts keep-only-if-not-worse for retrieval changes.
Two of the accepted rewrites concern memory inside a single run: bounded
prompts built from a summary of recent candidates, and a failure memory that
injects up to three recurring error signatures only when the bug rate is at
least 15%. These are within-run working memory, not a store kept for months.
The authors warn that noise compounds across both loops, and a single falsely
accepted rewrite becomes the new baseline. Their ignition test on three seeds
is inconclusive (final means 0.780 vs 0.782).

**What it would change here.** For task 02: before a replay delta is used to
accept a variant, measure the harness's own noise by replaying the baseline
over disjoint time windows. A variant should beat that spread, not merely
differ from it. The conditional failure memory is a second pattern, already
close to how this plugin behaves: inject only when a measured condition holds
(compare the evidence gate on per-prompt recall).
