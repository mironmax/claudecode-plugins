# Grounding Agent Memory: Environment-Probing Curation for Enterprise Agents

arXiv [2609.11060](https://arxiv.org/abs/2609.11060) v1, 10 Sep 2026. Microsoft.

**Claim.** Giving the asynchronous post-task memory curator read-only world
tools, so it can check, scope and refresh a candidate memory before writing
it, gives the best CLBench result in the study. Compared with no memory, pass
rate rises from 39% to 73% and reward from 8.60 to 22.60, while queries per
question fall from 8.8 to 4.7 and task-agent cost from $3.38 to $1.68.

**Conditions.**
- Models: GPT-5.4 for task agent, distiller and curator. No-drift replication
  on Sonnet 4.6 and Opus 4.7.
- Tasks: CLBench database exploration (40 questions, schema drift after
  question 20; a 30-question no-drift schedule) and 90 adapted APEX
  consulting tasks across six document worlds.
- Memory: indexed records carrying category, confidence, scope, lemma,
  provenance, utility and usage. The task agent reads only; the curator alone
  creates, updates and deletes.
- Who writes, and when: after each task closes, before the next is revealed.
- Horizon: tens of tasks per stream; five paired runs; 95% Student-t
  intervals.

**Applicability: partially; this is the closest match in the corpus.**
Curation here is likewise asynchronous and outside the agent loop (chores),
and the task agent is a fresh session each time. The key comparison is
probing against trajectory-only memory, and there the gain is smaller than
against no memory: pass 70±16 vs 73±5, reward 20.00 vs 22.60 (CLBench,
GPT-5.4). The no-drift lift is +0.075 on Sonnet 4.6 and +0.025 on Opus 4.7.
The authors themselves call the per-world variation a mechanism
interpretation, because the intervals overlap. Curation cost is excluded
from every cost figure.

**What it would change here.** Chores today run under an MCP-only allowlist
and cannot read the filesystem (task 03); task 03 answers this by having the
server precompute anchor candidates. The alternative this paper implies is
narrow read-only file access (read, glob, grep) for anchor and lift chores.
Testable in an A/B over the chores themselves: compare the decline rate, the
count of `touches` edits that are later reverted (from git history), and the
later endorsement of touched nodes, between precomputed-candidate chores and
read-only-probing chores.
