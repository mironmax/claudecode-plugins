# STALE: Can LLM Agents Know When Their Memories Are No Longer Valid?

arXiv [2605.06527](https://arxiv.org/abs/2605.06527) v1, 7 May 2026. *Addition to the starting corpus.*

**Claim.** When a later observation invalidates an earlier memory without
saying so, the best evaluated model reaches 55.2% overall (Gemini-3.1-pro).
Rejecting a query that presupposes the stale state is the weakest skill:
Gemini-3.1-pro scores 92.0% at recognising the change but 30.0% at resisting
the premise (Type I). A write-side adjudication prototype (CUPMem) reaches
68.0% on the same GPT-4o-mini backbone, against 8.7% for the plain model.

**Conditions.**
- Models: GPT-4o-mini, GPT-5.4(-nano), Gemini-3.1-pro/flash-lite,
  Llama-3.3-70B, Qwen3.5-9B/27B, MiniMax-M2.5. Memory frameworks (LightMem,
  Zep, LiCoMemory, A-mem, mem-0) all run on GPT-4o-mini.
- Data: 400 LLM-generated, expert-reviewed scenarios, each probed three ways
  (1,200 queries), inside haystacks of up to 150K tokens.
- Conflict types: Type I, the same attribute with an incompatible new value;
  Type II, a change to a related attribute that propagates to an old belief.
- Judge: Gemini-3.1-flash-lite, with 95.8% agreement with human judgments.
- Horizon: a single conflict per instance; memory is built once, then probed.

**Applicability: partially.** The benchmark concerns personal-assistant
attributes, not engineering decisions. The structure transfers, however.
Project knowledge is superseded implicitly too: a later decision makes an
earlier constraint obsolete without mentioning it. The Type II case maps onto
edges, where a change to one node leaves its neighbours asserting something
no longer true. CUPMem is the authors' own prototype with a fixed schema,
evaluated on their own benchmark.

**What it would change here.** Testable from storage-root git history: when a
node's gist is rewritten, or a node is archived as superseded, how often are
its edge-neighbours rewritten within the following N days? A low rate beside
high neighbour endorsement would suggest propagation is being missed. A
propagation chore (listing the neighbours of a changed node as revalidation
candidates) is the proposal this paper implies; its value is unmeasured here.
